gcloud CLI, 처음부터 공부하는 중

September 30, 2026

왜 공부를 시작했나

서비스가 GKE 위로 옮겨 가면서 같은 앱이 파드 여러 개로 뜨기 시작했습니다. 오류가 나면 대시보드를 열어 보는데, 어느 파드에서 났는지, 어느 배포 이후에 났는지 이어 붙이기가 어려웠습니다. 다른 사람이 터미널에서 gcloud 를 치는 걸 봐도 무슨 뜻인지 몰랐습니다.

그래서 gcloud CLI 를 처음부터 공부하고 있습니다. 아직 모르는 게 더 많고, 이 글은 지금까지 이해한 만큼의 기록입니다.

gcloud 는 무엇인가

Google Cloud 전체를 터미널에서 다루는 CLI 입니다. 웹 콘솔에서 클릭으로 하던 일 — 로그인, 프로젝트 선택, 클러스터 조회, 로그 조회 — 을 명령으로 합니다.

용어지금 내가 이해한 뜻
프로젝트Google Cloud 리소스를 묶는 단위. 대부분의 명령이 "어느 프로젝트에서" 를 전제로 한다
구성(configuration)계정·프로젝트·리전 기본값 묶음. 여러 개 만들어 두고 바꿔 가며 쓸 수 있다
클러스터GKE 가 관리하는 서버 묶음 전체
Cloud Logging파드가 표준 출력으로 찍은 로그가 모이는 곳

1. 로그인과 프로젝트 설정

# 구글 계정으로 로그인
gcloud auth login

# 작업할 프로젝트 지정 (이후 명령의 기본값이 된다)
gcloud config set project <PROJECT_ID>

# 지금 어떤 계정·프로젝트로 설정돼 있는지 확인
gcloud config list

명령이 엉뚱한 결과를 낼 때는 대개 다른 프로젝트를 보고 있었습니다. 그래서 gcloud config list 를 제일 먼저 치는 습관을 들이고 있습니다.

2. 클러스터 찾고 접속하기

# 이 프로젝트에 있는 GKE 클러스터 목록
gcloud container clusters list

# 클러스터 인증에 필요한 플러그인 설치 (처음 한 번)
gcloud components install gke-gcloud-auth-plugin

# 클러스터 접속 정보를 로컬(~/.kube/config)에 저장
gcloud container clusters get-credentials <CLUSTER> --region <REGION>

get-credentials 는 클러스터에 붙을 자격을 로컬에 받아 오는 명령입니다. 이걸 해야 클러스터 안쪽을 보는 도구들이 동작합니다.

3. 로그 찾기

파드는 언제든 죽고 새로 생기는데, 사라진 파드의 로그도 Cloud Logging 에는 남아 있습니다. gcloud logging read 로 조건을 걸어 찾습니다.

# 최근 1시간, 컨테이너 web 의 ERROR 이상 로그 20개
gcloud logging read \
  'resource.type="k8s_container" AND resource.labels.container_name="web" AND severity>=ERROR' \
  --freshness=1h --limit=20

# 특정 파드 하나의 로그만
gcloud logging read \
  'resource.type="k8s_container" AND resource.labels.pod_name="<POD>"' \
  --freshness=1h --limit=50

작은따옴표 안의 조건문은 웹 콘솔 로그 탐색기에 입력하는 필터와 문법이 같습니다. 콘솔에서 필터를 만들어 보고 그대로 복사해 오는 식으로 익히고 있습니다.

아직 모르는 것

  • 로그가 아닌 쿠버네티스 이벤트는 얼마나, 어디에 남는지
  • 여러 파드에 흩어진 로그를 요청 하나 단위로 묶어 보는 방법
  • get-credentials 로 받아 온 자격이 정확히 어떻게 인증에 쓰이는지

정리

아직 명령어를 익히는 단계이고, 원인을 바로 찾아내지는 못합니다. 그래도 어느 프로젝트를 보고 있는지 확인하고, 사라진 파드의 로그를 찾을 수 있게 된 것만으로 대시보드를 볼 때 막막함이 조금 줄었습니다. 쿠버네티스 환경을 직접 겪어 볼 수 있어서 만족하고, 계속 공부하면서 이 글을 채워 가려고 합니다.
